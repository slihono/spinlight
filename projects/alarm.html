01 / THE FIRST ATTEMPT

The version that stopped at the soldering iron.

The original idea was a smart alarm clock that could play music from a microSD card, display the weather, time and date, and eventually support voice recognition.

I had written most of the software when I accidentally burned the microSD adapter while soldering it. The project came to a stop. Getting the software ready had not been enough to finish the device.

02 / A DIFFERENT PLAN

Restart with what was already on the table.

What brought me back was noticing how different my mornings felt when I woke up to music. That was enough motivation to revisit the project.

This time, I simplified the design around the components I already had: internet radio that starts at alarm time, time/date/weather information, and an embedded web server to configure the alarm from my phone.

I also explored Spotify integration before choosing a direct internet radio stream. The rebuild had a clearer direction.

“I challenged myself to build it using only the components I already had.”

03 / READING THE SCREEN

The backlight was only the beginning.

The LCD could light up and still show strings of unreadable characters. Fixing unstable I2C communication with the screen became one of the main debugging tasks.

The clean “Bonjour Seneve!” welcome message was a different kind of milestone: readable text coming out of the hardware. Other tests recorded the name display, symbols, Wi-Fi initialisation and unavailable weather information.

Powering the screen and getting readable text were two different milestones.

04 / BUILDING A BODY

A LEGO case for a real circuit.

I did not have a case or access to a 3D printer. My solution was to build an enclosure with LEGO bricks I found at home.

Building around the LCD turned a flat module into something I could hold, set on a desk and open again while testing the wiring. The frame changed as I tried different arrangements around the screen.

05 / MAKING IT WORK TOGETHER

One small computer. Several jobs.

The ESP32 had to handle audio, the alarm configuration page and physical controls. My biggest software lessons came from making those jobs coexist.

Keep the controls responsive.

I worked on MicroPython so the web server could stay responsive while the program handled physical button inputs.

Work within the memory budget.

I2S audio streaming exposed RAM limitations. Those limits had to be considered alongside the rest of the program.

Find the audio, not just a radio page.

A radio station's web page was not the audio stream itself. Finding direct MP3 streams became part of the debugging work.

06 / THE FIRST BUILD

A first version, with a story behind it.

This is the first completed version of My First Alarm. The build ended up with internet radio as its music source and a LEGO enclosure shaped around the LCD.

The photographs keep the less polished moments too: blank displays, character tests and leads still outside the housing. Together, they show how the device took shape.

The lessons I kept.

Embedded programming, hardware debugging and soldering all became part of the same project. I originally expected a one-day build. Working through the setbacks taught me far more than that first estimate allowed for.
